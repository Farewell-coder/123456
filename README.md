# My Life, My Sim

一款**纯前端、可离线运行**的中文人生模拟器。抽天赋 → 分配属性 → 一年一年地过 → 死亡时结算评级，附一段墓志铭。

Android 端由 WebView 壳承载，游戏本体是一套零依赖的原生 JavaScript 单页应用。

---

## 玩法

1. **抽天赋** —— 从 119 个天赋中抽取开局词条，稀有度分白 / 蓝 / 紫 / 橙
2. **分配属性** —— 基础 6 项：颜值 / 智力 / 体质 / 家境 / 幸运 / 快乐
3. **逐年推进** —— 从 0 岁到寿终，每年一次事件
4. **结算** —— 死亡时按属性组合判定结局（37 个专属结局 + 综合评分），附一段墓志铭

隐藏属性 4 项：情商 / 意志力 / 心理健康 / 社会影响力。归零会触发特殊走向。

---

## 特性

- **可离线**：自带 4605 条事件库（六阶段每段 ≥300 条），关掉 AI 也能完整走完一生
- **可联网**：接入任意 OpenAI 兼容接口，由模型现场生成年度事件、墓志铭与对话
- **本地存档**：所有数据只留在这台设备上，不上传任何服务器
- **图鉴系统**：跨周目累积已见事件、天赋、结局
- **内容库**：支持导入 / 导出自定义事件、天赋、成就、结局，并可标记来源（本地 / 外部 / AI 加入）
- **深浅色主题**：跟随系统暗色模式开关
- **因果链**：属性与状态标签会影响后续事件的走向，而不是纯随机抽卡
- **不加密**：`minifyEnabled false`，APK 里的 `assets/` 就是可读源码，改一行不用反编译

## AI 配置

游戏**不内置任何 API Key**。在「设置 → AI」里填入你自己的 OpenAI 兼容端点与密钥即可：

| 项 | 说明 |
|---|---|
| API 提供商 | 内置 DeepSeek / Moonshot / OpenAI / 硅基流动 / 阿里云百炼 / 智谱 / OpenRouter 等预设，也可自定义 |
| API Key | 仅保存在本机，不会外传 |
| 模型 | 可拉取端点下的模型列表后选择 |
| AI 占比 | 0–100%，控制 AI 生成事件与本地事件库的比例 |

> 端点与密钥都由你自己提供，作者不提供、不代管、不收集任何凭据。

## 构建
需要 Android SDK 与 JDK 17：
```bash
# Windows
gradlew.bat assembleRelease
# Linux / macOS
./gradlew assembleRelease
```

签名配置从工程外的 `keystore.properties` 读取（见 `app/build.gradle`），该文件不入库。
`storeFile` 支持两种写法：绝对路径（CI 用），或相对 `keystore.properties` 所在目录的
文件名（本地用，换机器不用改）。密钥找不到时构建会打 warning，不会静默产出未签名包。

最低支持 Android 8.0（API 26），目标 API 34。

> 只想改游戏内容的话不需要编译环境：`app/src/main/assets/` 是零依赖的纯前端代码，
> 直接用浏览器打开 `index.html` 就能预览（只有 AI 联网与「导出到下载目录」会失效）。

## 数据来源

内置事件库共 **4605 条**（运行时 `builtinEv().length` 口径），全部以「本地」来源标记
（只读、不可删、不进备份）。按 id 前缀可精确归类到来源：

| id 前缀 | 条数 | 来源 | 说明 |
|---|---|---|---|
| `幼年0`…`老年57` | 421 | `DB` | 六阶段基础事件池（手写，带完整扩展字段） |
| `hn0`…`hn923` | 924 | `DB_HN` | 扩充事件库，来自作者自有文档《内容补充》，逐条审核与合规化清洗后并入 |
| `g0_0`… | 105 | `DB_TAG_EV` | 标签事件，抽到即解锁对应状态标签 |
| `x幼年0`… | 108 | `DB_EXT_EV` | 本地扩展池 |
| `d中年0`… | 49 | `DB_DYING_EV` | 临终症状池（剩余寿命 ≤ 4 年时优先抽取） |
| `axINT_0`… | 65 | `DB_ATTR_EV` | 属性专属池（某项属性达门槛才出现） |
| `f幼年0`… | 43 | `04-ai.js` 内联 | 女性专属事件 |
| `u童年0`… | 651 | `04-ai.js` 内联 | 早期版本收集的事件文案，审计通过后升格为内置 |
| `u1_7`… | 101 | `DB_USER_EV` | 早期客户端分组数据（与上一行同文案的已合并） |
| `n幼年0`…`n老年0`… | 2138 | `DB_NEW_EV` | 本次扩充事件库（v0.0.3），六阶段各一批，逐条按写作规范校验后并入 |

> 注意：**不要用原始声明表相加来核对条数**。原有声明表加总是 2714 条，但 `builtinEv()`
> 结尾有一段「同文案合并」（见 `04-ai.js`）——同一句话同时出现在旧表与批量注入行时
> 只保留一条，共合并掉 247 条。2714 − 247 = **2467**，再加上本次新增的 **2138** 条，
> 才是运行时真正进池的 **4605** 条。

除事件外，其余五类同样在 v0.0.3 做了扩充（原有 → 现有）：
天赋 **59 → 119**、成就 **40 → 80**、结局 **17 → 37**、标签 **54 → 87**、墓志铭 **25 → 85**。
六类合计 **4605 + 119 + 80 + 37 + 87 + 85 = 5013 条**。

扩充事件库的原始落盘文件为 `hn_events.min.json`，内容已内联进 `04-ai.js` 的 `DB_HN` 常量；
该 JSON 仅作构建期数据源保留，游戏运行时不读取（源码包中未附带该文件）。

AI 在游玩过程中现场生成的事件文案，由玩家自行决定是否入库（来源标记为「AI 加入」），不会自动上传到任何服务器。
